# Support PhpStorm 2026.3 (build 263)

## Request
make the plugin work for "Build #PS-263.7307.215, built on November 5, 2026"

## Analysis
A change: the plugin exists and works, but its declared range stops at `262.*`
(`build.gradle.kts:58`, `untilBuild.set("262.*")`), so an IDE of the 263 family (2026.3) refuses
to load it. The locally installed PhpStorm is exactly this build
(`/Applications/PhpStorm.app/Contents/Resources/build.txt` = `PS-263.7307.215`), and JetBrains
lists it as the 2026.3 release of 2026-11-05, so the Plugin Verifier can download it.

Raising `untilBuild` only makes the IDE accept the plugin. Two more things decide whether it works:

- **Binary compatibility**: the 1.0.2 release had to replace an internal API call for 262. The
  Plugin Verifier has not been run against 263 yet (Docker was down during planning).
- **Reflection, invisible to the verifier**: `TerminalCommandRunner.kt` reaches the terminal through
  `Class.forName`. Checked during planning against `plugins/terminal/lib/terminal.jar` of both
  PS-262.10968.76 and PS-263.7307.215: the signatures are identical. `TerminalService` exists in
  neither (first attempt always falls through), `TerminalView.getInstance(Project)` +
  `createLocalShellWidget(String, String)` + `ShellTerminalWidget.executeCommand(String)` exist in
  both. So 263 takes the same runtime path as 262 and no Kotlin change is expected. These methods
  are deprecated; moving off them is the separate item
  `docs/todo/2026-11-06.change.migrate-terminal-api.md`.

## Impacted files
- `build.gradle.kts`: `untilBuild` to `263.*` with its comment, the default verifier IDE and the
  example in the verifier comment.
- `CHANGES.md`: new top line for `1.1.1`.
- `CLAUDE.md`: the two mentions of the `251-262.*` range (lines 7 and 67).
- Kotlin sources under `src/main/kotlin/com/forret/llmbrains/`: only if the verifier reports a
  problem on 263.

## Plan
See the PRP below.

## Acceptance criteria
- The packaged `plugin.xml` declares `since-build="251"` and `until-build="263.*"`.
- `./gradlew build` and `./gradlew test` pass.
- The Plugin Verifier reports `Compatible` against `PS-263.7307.215` with no "Internal API usages"
  section.
- In PhpStorm 2026.3 (build 263.7307.215) the plugin loads, the 🫴 toolbar button shows, and
  choosing an agent opens a terminal tab that runs its command.
- `CLAUDE.md` names the range `251-263.*` and `CHANGES.md` has a `1.1.1` line for 2026.3.
- Nothing is committed, tagged or pushed, and `VERSION.md` is unchanged.

## PRP

### Goal
The plugin ZIP built from this repo is accepted by, and works in, IDEs of the 263 family
(PhpStorm 2026.3, build 263.7307.215) while still supporting 251 and later. The declared range,
the verifier default and the docs all say 263, and a `1.1.1` changelog line is ready for the release.

### Why
- PhpStorm 2026.3 was released on 2026-11-05 and marks the plugin as incompatible, so users who
  upgrade lose the toolbar button.
- Same routine as the earlier range raises (`0.5.3` for 2026.1, `0.5.4` for 2026.2, verified in `1.0.2`).

### Decisions taken
- Where does the item end? → Before the release: no `setver`, no commit, tag, push or Marketplace
  upload. The user runs the `release-plugin` skill afterwards. (user)
- Which version does the `CHANGES.md` line carry? → `1.1.1`, the patch after the current `1.1.0`,
  matching `setver ap` in the release skill. (user)
- Deprecated terminal API (`TerminalView.createLocalShellWidget`, called by reflection)? → Keep it
  unchanged in this item; the migration is filed as
  `docs/todo/2026-11-06.change.migrate-terminal-api.md`. (user)
- Compile target? → Stays IntelliJ IDEA 2025.1 (`intellij { version.set("2025.1") }`), because
  `sinceBuild` stays 251. (default)
- Default verifier IDE in `build.gradle.kts`? → `PS-2026.3`; comment example
  `PS-263.7307.215,IC-2026.3`. (default)

### Known gotchas & guardrails
- Mirror the existing patterns named under Context; do not introduce new ones for this item.
- CRITICAL: `./gradlew` needs Docker Desktop running. `docker info` failing means every Gradle call
  fails with an easy-to-miss "Cannot connect to the Docker daemon"; start it with `open -a Docker`
  and wait. There is no local JDK, so no `java`, `javap` or plain `gradle`.
- There is no `ktlintFormat` task, despite `CLAUDE.md`; skip it.
- Test stderr is only visible in `build/test-results/test/*.xml`.
- The verifier downloads PS-263.7307.215 (about 1 GB) into
  `~/.cache/mkdox-gradle/gradle/pluginVerifier/ides/`. If the download fails, copy
  `/Applications/PhpStorm.app/Contents` to that folder as `PS-263.7307.215` and pass
  `-PverifierLocalIde=/gradle-cache/pluginVerifier/ides/PS-263.7307.215` (Docker Desktop does not
  share `/Applications`).
- Treat every "Internal API usages" line as something to fix. In 262 all plugin-descriptor lookups
  were internal, which is why the plugin reads its version from its own `META-INF/plugin.xml`
  resource; keep that.
- PRESERVE: `sinceBuild` 251, the 2025.1 compile target, gradle-intellij-plugin `1.17.3` (no
  migration to the 2.x IntelliJ Platform Gradle Plugin), and `TerminalCommandRunner.kt`.
- PRESERVE: `VERSION.md` stays `1.1.0`; `setver` writes it at release time. The ZIP built here is
  therefore `llm-brains-1.1.0.zip` although the changelog line says `1.1.1`.
- Do not commit, tag or push, and do not run `setver` or `./build.sh` (it is fine, but
  `./gradlew build` already builds the ZIP).
- Also update together: `untilBuild` and its comment, the verifier default and its comment example,
  `CLAUDE.md` lines 7 and 67, and the `CHANGES.md` top line.
- In this zsh, unquoted variables are not word-split and `echo =====` fails; quote separators and
  pass arguments individually.

### Approach
Three files change. `build.gradle.kts` gets the new upper bound (`263.*`, comment naming 2026.3)
and the new verifier default. Then build, test and run the verifier against PS-263.7307.215; fix
whatever it reports in the Kotlin sources, keeping the change minimal and compatible with 251. Only
when the verifier is clean, update `CLAUDE.md` (range) and add the `1.1.1` line on top of
`CHANGES.md`, saying 2026.3 is supported and verified against build 263.7307.215 (plus any API fix
made). Finish with the manual check in the real IDE, which the user performs: build the ZIP, open
`build/distributions/`, and ask the user to install it from disk in PhpStorm 2026.3 and confirm.
If the user cannot test right away, leave the item busy and mark it with `/fodo:wait`.

### Validation loop (executable, in order)
```bash
# Level 0 — Docker is up
docker info >/dev/null 2>&1 || { open -a Docker; until docker info >/dev/null 2>&1; do sleep 3; done; }

# Level 1 — build + unit tests (no new tests: no behaviour changes; existing suites must stay green)
./gradlew build --console=plain 2>&1 | tail -5     # expect: BUILD SUCCESSFUL
./gradlew test --console=plain 2>&1 | tail -5      # expect: BUILD SUCCESSFUL

# Level 2 — declared range in the packaged plugin
T=$(mktemp -d) && unzip -o -q "build/distributions/llm-brains-$(cat VERSION.md).zip" -d "$T" \
  && unzip -p "$T"/llm-brains/lib/instrumented-llm-brains-*.jar META-INF/plugin.xml | grep idea-version
# expect: since-build="251" until-build="263.*"

# Level 3 — binary compatibility
./gradlew runPluginVerifier -PverifierIdes=PS-263.7307.215 --console=plain 2>&1 \
  | grep -E 'Compatible|Internal API|Deprecated|BUILD'
# expect: "Plugin com.forret.llmbrains:1.1.0 against PS-263.7307.215: Compatible" and BUILD SUCCESSFUL,
# no "Internal API usages" line. Full report: build/reports/pluginVerifier/

# Level 4 — docs and guardrails

grep -n '263' build.gradle.kts CLAUDE.md           # expect: untilBuild, verifier default, both CLAUDE.md lines
head -1 CHANGES.md                                 # expect: - `1.1.1`: ... 2026.3 ... 263.7307.215 ...
cat VERSION.md                                     # expect: 1.1.0
git status --short                                 # expect: only build.gradle.kts, CHANGES.md, CLAUDE.md, docs/todo/ (plus sources if the verifier needed a fix)

# Level 5 — manual check by the user in PhpStorm 2026.3 (build 263.7307.215)
open build/distributions/
# Settings > Plugins > gear > Install Plugin from Disk > llm-brains-1.1.0.zip, restart.
# expect: plugin enabled without "incompatible" warning; 🫴 button in the main toolbar; choosing an
# agent opens a terminal tab titled after the agent that runs its command; Settings submenu >
# "check" opens a terminal tab with the check output.
```

- Manual check in PhpStorm 2026.3: user report, "it works when installed from a zip". This is the user's overall verdict; the individual Level 5 points (no incompatibility warning, 🫴 button, agent tab, check tab) were not reported or re-checked separately.

### Deviations from the spec
- Level 4 expected `grep -n '263'` to list the verifier default, but that default reads `PS-2026.3`, so it does not match. The default is what the PRP decided; only the expected output was off.
- Otherwise none. No Kotlin source changed, and the local-IDE verifier fallback was not needed.

### Discoveries
- Building with `VERSION.md` still at `1.1.0` overwrote `build/distributions/llm-brains-1.1.0.zip`. It now declares `until-build="263.*"` and differs from what was tagged `v1.1.0`, so it must not be uploaded as 1.1.0; `setver` has to run first.

- The verifier's "Compatible" does not cover the reflective terminal calls in `TerminalCommandRunner.kt`, so the manual check is the only runtime evidence for them on 263. They use deprecated methods; see `docs/todo/2026-11-06.change.migrate-terminal-api.md`.
